# Contract 1.14: additions

This page lists what contract 1.14 adds to [contract 1.0](README.md) and the pages of 1.1 to 1.13
([1.1](README-1.1.md), [1.2](README-1.2.md), [1.3](README-1.3.md), [1.4](README-1.4.md), [1.5](README-1.5.md),
[1.6](README-1.6.md), [1.7](README-1.7.md), [1.8](README-1.8.md), [1.9](README-1.9.md), [1.10](README-1.10.md),
[1.11](README-1.11.md), [1.12](README-1.12.md) and [1.13](README-1.13.md)). Those pages are still normative and
unchanged: a minor version only adds files, this page among them. The contract's version is the one `lock.json` records
(`contractVersion`), which the .NET suite holds in `ContractFiles.ContractVersion`.

A port that passes contract 1.14 passes every 1.0 to 1.13 fixture and the fixtures below.

## Three .NET features, now in the ports

Up to 1.13 three things existed only in .NET:

- **Exporting measured lessons.** `AgentExperienceLessons.ExportMeasuredAsync` hands every lesson the injection
  holdout measured as helping to a sink, and the built-in
  [`MarkdownLessonFileSink`](../src/AgentExperience.MicrosoftAgentFramework/Export/MarkdownLessonFileSink.cs) keeps a
  Markdown file other tools load (an `AGENTS.md`, a `CLAUDE.md`, a skill folder).
- **The lessons page.** [`ExperienceLessonsHtml`](../src/AgentExperience.MicrosoftAgentFramework/ExperienceLessonsHtml.cs)
  renders a lessons page (1.7) as one HTML document. [1.7](README-1.7.md) said a port does not; from 1.14 a port does.
- **The model-backed reflector.** [`ChatClientExperienceReflector`](../src/AgentExperience.MicrosoftAgentFramework/Reflections/ChatClientExperienceReflector.cs)
  asks a chat client for a reflection's free text, and finalization screens what it writes with the content guard for
  model-authored text ([Finalization](../docs/guide/finalization.md#model-backed-reflection)).

From 1.14 a port offers all three with .NET's defaults and validation, and its output is byte-identical to .NET's for
the same input. The deterministic reflector stays the default: nothing calls a model unless the host configures the
model-backed reflector. **A port that does not implement 1.14 keeps passing 1.13**, and with nothing configured nothing
changes.

## What 1.14 adds

- **Fixtures** (no database): `lesson-export` (eight cases), `lessons-html` (five), `reflection-prompt` (six),
  `reflection-output` (thirty-one), each generated by the .NET classes above, run the way a host runs them, and
  `content-guard`, a differential corpus of what .NET's content guard answers.
- **Rules:** the export's selection and file, the page's encoding, and the reflector's request, reading and failure
  classes, with the screening of model-authored text.

Nothing else changes: no SQL, no schema object, no privilege. A model-authored record is stored exactly as 1.0 stores
any record: its reflection's `authorship` is `Model` (1.0's optional payload member, written only when it is not
`Deterministic`).

## Exporting measured lessons

**The set.** For an identity (its authorization and scope), the export reads the lessons view (1.7) of exactly that
scope, with the statuses retrieval can return (`Validated`, `Reinforced`), up to 500 records and ineligible lessons left
out, at the setup's clock (`exportedAt`). Then:

1. A page that is not `Found` (the scope lies outside the authorization) ends the export with that outcome: the sink is
   not called and no file is written.
2. A page with more lessons than one read answers (`hasMore`) is refused (.NET throws `InvalidOperationException`; a
   port raises or returns its own error): a sink given part of the set would remove copies of lessons that still help.
3. One benefit estimate (1.9) for the scope, over the assignments within the benefit policy's window before
   `exportedAt` (30 days by default), at the minimum runs per arm the caller gives, or the policy's (20 by default). A
   minimum below 1 is refused before anything is read. An estimate that is not `Found` ends the export with its
   outcome, the sink not called.
4. When the store tracks the holdout, a lesson is in the set when it is eligible (1.7), its record's outcome is
   `Verified`, and its verdict is `Helps`; each once, **sorted by experience ID** (the lower-case hyphenated text,
   ordinally). When the store does not track the holdout, the set is empty and `holdoutTracked` is false.
5. The sink is called with the whole set, an empty one included, so it can remove stale copies. What it raises
   propagates; a sink that returns nothing is an error.

**Each exported lesson** carries its experience ID, its record's revision, its task ID, `exportedAt`, the measured
comparison (1.9's comparison form) and its **lesson text**: the record's lesson as the verbose Historical Reference
block renders it for the reader's own record (1.0), with the port's injection options (failure detail, argument
allowlist), **without** the block's begin and end lines, the record's delimiters, or its source, confidence, ranking,
`Recorded:`, `Environment:`, `Verification:` and `Evidence:` lines: for a deterministic reflection, `Lesson:`, the
`Tried:` and `Worked:` lines, `Reuse guidance:`, `Preconditions:` and `Warnings:`; for a model-authored one, the `Tried:`
and `Worked:` lines first, then the same reflection lines between the fixed `Authored:` and `End authored:` lines.

**The sink.** A port defines its own sink interface: one call that brings the sink's copy of a scope's lessons in step
with the set (adds what it lacks, updates what changed, removes what is no longer in the set) and returns how many it
added, updated and removed. The built-in Markdown sink keeps one file:

```
# Measured lessons

Exported: <exportedAt as yyyy-MM-ddTHH:mm:ss.fffffffZ, the sink's own clock>

These lessons were learned ... and any edit is lost.

Scope:

    tenant: <tenant>
    application: <application>
    project: <project>
    team: <team>              (only when set; then agent, then user, likewise)

Lessons: <count>
```

then, for each lesson in the set's order (the sink sorts by experience ID itself and keeps the first of a repeated
ID):

```

## Lesson <experience ID>

Revision <revision>. Measured benefit: given it, <s> of <n> runs verified (<rate>%); denied it, <s> of <n> runs verified (<rate>%); difference <d>, 95% interval <lower> to <upper> (Helps).

    Task: <task ID>
    <lesson text, every line>
```

- The fixed sentences are .NET's, word for word (`MarkdownLessonFileSink.cs`); the file is UTF-8 without a byte order
  mark, LF only, ending in one LF.
- **Code blocks.** Everything drawn from a record or the scope is an indented code block: the text's CR LF and lone CR
  become LF, trailing LFs are removed, and each line is written with four spaces before it, a blank line left empty.
  So no lesson can add a heading, a link or an instruction outside its block.
- **Numbers.** A rate is `rate × 100` rounded to a whole number, half away from zero (.NET's `ToString("0")`), and the
  `(<rate>%)` is left out when the arm has no rate. The difference and the interval are written only when all three
  are numbers, each as .NET's `"+0.00;-0.00;0.00"`: two decimals, half away from zero, `+` before a positive value,
  `-` before a negative one, and `0.00` for a value that rounds to zero; `(unavailable)` for one that is not finite.
  The verdict is always `Helps`.
- **Counting.** The sink reads the file as it was (none: nothing held). A line that starts exactly with `## Lesson `
  followed by a GUID in the D form (8-4-4-4-12 hexadecimal digits, either case, with any white space before or after
  it trimmed, as .NET's GUID parser trims `char.IsWhiteSpace` characters, the no-break space included) opens a section, which runs to the next
  such line, and is that lesson's previous section from the blank line before its heading (the text before the first
  heading belongs to none); the first section of a repeated ID counts. A lesson whose section is new is **added**, one
  whose section differs from its previous one **updated**, and an ID the file held that the set lacks **removed**.
  The file is read as UTF-8 with a leading byte order mark, if any, dropped (.NET's `File.ReadAllText`).
- **The write.** The whole file is written to a temporary file in the same directory, then moved over the file, so a
  reader sees the old file or the new one; a failure removes the temporary file and propagates. The file is created
  with .NET's mode on Unix, read and write for everyone less the process's umask (`0666 &^ umask`, so `0644` under the
  usual umask), never owner-only, and the file written has no byte order mark. The directory must
  exist. The path is the caller's: .NET refuses only a blank one, resolves it to a full path, and confines it to
  nothing, so neither does a port (a host that takes the path from configuration it does not trust checks it first).

## The lessons page

A port renders a lessons page (1.7's, with its scope) as .NET's `ExperienceLessonsHtml.Render` does: the same document,
byte for byte. The fixed markup, style sheet and sentences are .NET's; the rules that make it byte-identical:

- **Encoding.** Every value drawn from a record or the scope (task IDs, check IDs, evidence kinds, the block, the
  ineligibility reason, scope segments, the outcome) is encoded as .NET's `WebUtility.HtmlEncode` encodes it: `<`, `>`,
  `&`, `"` and `'` as `&lt;`, `&gt;`, `&amp;`, `&quot;` and `&#39;`; every character from U+00A0 to U+00FF as a decimal
  reference (`&#233;`); a character outside the Basic Multilingual Plane as one decimal reference to its code point
  (`&#128512;`); a lone surrogate as U+FFFD; everything else as it is.
- **Numbers and instants.** The confidence as 1.7's two decimals (`(unavailable)` when not finite); an instant in UTC as
  `yyyy-MM-dd HH:mm:ss UTC`, its fraction of a second cut, never rounded; a count in decimal.
- **The parts, in order:** the banner; `What it learned`; the scope (`tenant … / application … / project …`, then
  ` / team …`, ` / agent …`, ` / user …` when set) and when the page was read; then either the store's outcome (not
  `Found`), `No lessons yet.` (none), or how many are shown (`1 lesson`, `<n> lessons`) with the sentence about more when
  `hasMore`, and each lesson; then, when `outOfScopeDropped` is above 0, how many records were left out.
- **A lesson:** its task ID; its status and eligibility badges; its confidence, stored and last-activity instants, last
  injection (`<instant> (<n> time)` or `times)`, `never` when injections are tracked, `not tracked` otherwise) and
  experience ID; its checks table, each result's class `eligible` (`Pass`), `failed` (`Fail`) or `warn` (anything
  else), or `No verified checks recorded.`; and its block, after the sentence for an eligible or an ineligible lesson.
- **The policy.** The document carries a `Content-Security-Policy` meta tag that allows no script, no external
  resource and no form submission, and `no-referrer`.

**Serving it** is idiomatic per port and not fixtured: Python offers a handler function independent of ASGI and WSGI,
Go an `http.Handler`. Each sends the document as `text/html; charset=utf-8` with exactly the headers the
[deployment guide](../docs/guide/deployment.md)'s .NET endpoint sets, `Cache-Control: no-store`, `X-Frame-Options: DENY`
and `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; frame-ancestors 'none'` (a `<meta>` policy
cannot set `frame-ancestors`), and no others. As that endpoint (`MapGet`) does, it answers `GET` only: any other method,
`HEAD` included, is `405 Method Not Allowed` with `Allow: GET`. A request the host's identity resolution gives no
identity is `403 Forbidden`, and one whose resolution or read fails is `500 Internal Server Error`, neither with a
body that says why. **Authorization is the host's:** the identity comes from the host's own authentication, never from
the request's query or body, and the page discloses every lesson in the scope.

## The model-backed reflector

**Options**, with .NET's defaults and validation (an invalid value refused when it is set or when the reflector is
built):

| Option | Default | Valid |
| --- | --- | --- |
| `ModelName` | none | none, or not blank |
| `Timeout` | 30 s | above 0, at most `int.MaxValue` ms |
| `MaxQuotedLength` | 500 | at least 16, and below `MaxPromptLength` |
| `MaxPromptLength` | 16,000 | at least 1,000 |
| `Temperature` | 0 | none, or finite and not negative |
| `MaxOutputTokens` | 2,048 | above 0 |
| `ConfigureChatOptions` | none | the host's callback on each call's request options (not fixtured) |

Lengths are UTF-16 code units, as everywhere in the contract.

**The request.** One call per reflection, with two messages: the system prompt (`ChatClientExperienceReflector.SystemPrompt`,
word for word) and, as the user, the **data message** (`ReflectionPromptBuilder`): the untrusted-data preamble, the
task text (or the task ID when there is none), the verification status, the passed and failed check IDs and the
evidence IDs (each distinct, in order), then the attempts oldest first, each with its ordered tool names, each call's
error and result, and the attempt's error and result. Every captured string is a quoted span: escaped first (`\"`,
`\\`, `\r`, `\n`, and `\uXXXX`, upper-case hexadecimal, for C0 including tab, DEL, C1, U+061C, U+200B to U+200F, U+202A
to U+202E, U+2028, U+2029, U+2060 to U+2069, U+FEFF and a lone surrogate), then clipped to `MaxQuotedLength` (tool names
and check IDs to the smaller of it and 128) with `…` as its last character, never inside an escape or a surrogate
pair. Each header list names at most 32 IDs and counts the rest; when the header and the attempts section's fixed
lines do not fit `MaxPromptLength`, the lists shrink to 8, then 1, then 0 IDs; the attempts are then kept newest first
while they fit, the oldest left out with a note. When not even the smallest header fits, nothing is sent
(`PromptTooLarge`).

The request options: the model (`ModelName`, none when unset), the temperature, the output cap, **no tools and a tool
mode of none** (re-asserted after the host's callback, with the output cap), and structured output with the schema
named `experience_reflection` that `expected-options.json` holds, member for member. A port maps these onto its own
chat client's options and says how in its README.

**Reading the answer.**

1. A response that carries a function call or a function result anywhere: `ToolCallAttempted`.
2. The text contents of the assistant messages only, in order, joined; reasoning content and other roles' text are
   ignored. Over 65,536 UTF-8 bytes: `OutputTooLarge`, unread.
3. Trimmed; when, as a whole, it is one Markdown fence (a first line of exactly ```` ``` ```` or ```` ```json ````,
   less a CR at its end, and a last line of exactly ```` ``` ````), what is between, trimmed. It must then start with
   `{` and be one JSON object read strictly: no duplicated property, no comment, no trailing comma, members matched by
   exact name, unknown members ignored; `lesson` and `reuseGuidance` a string or null, the four lists an array of
   strings or nulls, or null. Anything else: `Unparseable`.
4. A missing, null or blank lesson: `EmptyLesson`.

**Assembling the reflection.** Every bound field (the reflection ID, the run ID, `createdAt`, the verification status,
completion score, rule version, and the evidence IDs, distinct in order) is copied from the request. Null and blank list
items are dropped; a blank reuse guidance is null. Successful approaches are kept only for a `Verified` run; a run that
is not verified gets the fixed warning and reuse guidance. A precondition the run did not capture (a blank runtime
version, operating system or application version, or a blank metadata value, in key order, never the model's own
metadata key) is added as `<label>: unknown`, with a warning, and the additions never push a list over 32 items: when
they do not fit, the model's list gives up its last items as needed and one line says how many more were not listed.
The producer is `AgentExperience.ChatClientExperienceReflector/1.0.0 (<model>)`: the response's model ID, else
`ModelName`, else `unknown`, skipping one that is blank, longer than 128 characters, contains `:` or `/`, or holds a
link (the content guard's rules), with each character outside `[A-Za-z0-9._:/@+-]` replaced by `_`, cut so the producer
fits 200 characters. **Authorship is `Model`.**

**Failures.** Anything short of a reflection fails with .NET's `ReflectionFailedException` equivalent, carrying a
**kind** (`ModelCallFailed`, `TimedOut`, `Unparseable`, `EmptyLesson`, `ToolCallAttempted`, `OutputTooLarge`,
`PromptTooLarge`, `ChatOptionsCallbackFailed`), the type name of the exception behind it (never its message) and .NET's
fixed message for the kind, in which a port names its own type. A call still running at `Timeout` is `TimedOut`, also
on a client that ignores cancellation (the call is abandoned); the caller's own cancellation propagates as the
language's cancellation. Finalization treats a failure as any reflector that throws: the record is stored
`Quarantined`, with no reflection.

**What it showed the model** (`GetReflectedRunContent`, `expected-shown.json`): the task text (or ID), the check IDs the
header lists, and the kept attempts' tool names, errors and results, each unescaped and cut exactly where its span was
cut (without the `…`), then each environment metadata key, cut to 200 characters. Screening compares links with it.

**Screening.** Finalization screens the reflection as 1.0 screens every reflection (the hygiene layer and its limits),
and then, because it is model-authored, with the **content guard** ([Finalization](../docs/guide/finalization.md#limits-of-model-authored-lessons)):
each screened field, after removing invisible characters, NFKC and removing them again, is refused as `UnsafeContent`
when it holds credential-shaped text, a word mixing Latin with Cyrillic or Greek letters, instruction-override phrasing
(also across all fields and list items joined), a `data:`, `javascript:`, `vbscript:` or `file:` link or a UNC path,
or a URL, hostname or IP address that is not, as a whole token, in what the reflector showed the model. The patterns
are .NET's, exactly ([`ModelTextPatterns.Shared.cs`](../src/Shared/ModelTextPatterns.Shared.cs)), applied as .NET
applies them, to UTF-16 code units (so a character outside the Basic Multilingual Plane is neither a letter nor a digit
to them; lower-casing is .NET's invariant per-unit mapping, which leaves U+0130 as it is). .NET bounds each match to one
second: a text of the run content that cannot be read in time admits nothing, and a field that cannot be checked in
time is refused (`text that could not be checked in time`); a port bounds its work the same way, by time or by size.
The refusal's reason names the field and the rule, never the text: `its Lesson contains credential-shaped
text`, `its Warnings[1] contains a URL that is not in the captured run`, `the text across its fields contains
instruction-override phrasing`. A port that kept a sanitizer layer for reflections runs it between the two, as .NET
does.

**Registration** is the port's one-call setup or a constructor, opt-in, replacing the deterministic reflector only
when asked. The reflector emits no telemetry of its own and no prompt or answer text reaches telemetry; a screening
refusal is the `finalize` span's `agentexperience.reflection.screening_refusal`, as in .NET.

**Where a port cannot match .NET** it says so in its README; none changes a fixture. A cause type is the port's own
type name. .NET refuses a chat client whose pipeline invokes functions; a port refuses one only where its framework
lets it see that (Python cannot; Go when the client says so), and a response carrying a tool call still fails as
`ToolCallAttempted`. A language without a Unicode normalizer in its core (Go) registers one from its MAF module. Unicode
tables differ by language and version, so the content guard's verdict on rare characters may differ. A Go string
cannot hold a lone surrogate: Go's screening removes each byte of invalid UTF-8 as .NET removes a lone surrogate, and
its HTML encoding writes U+FFFD for it as .NET does for a lone surrogate, but a case whose input is a lone surrogate
cannot be expressed in Go (the `content-guard` corpus marks it).

**A binding check or a screening that throws** (a reflector that returns something that is not a reflection, a
reflection missing a bound field, a guard that fails) never escapes finalization: as .NET's backstop, the record is
stored `Quarantined` with no reflection, and screening's refusal is `Unreadable`.

## The fixtures

```
fixtures/lesson-export/<case>/      seed.json + options.json [+ previous.md] -> expected.json + expected.md
fixtures/lessons-html/<case>/       page.json -> expected.html
fixtures/reflection-prompt/<case>/  input.json + reflector.json + reply.json -> expected-messages.json + expected-options.json + expected-shown.json
fixtures/reflection-output/<case>/  input.json + reflector.json + reply.json -> expected.json + expected-record.json + expected-event.json
fixtures/content-guard/cases.json
```

**lesson-export.** `seed.json` is the lessons-view seed form (1.7 and 1.10: `records`, `injections`, empty here, and
`assignments`): seed a store with it as for the lessons view, its clock `options.json`'s `now`. `options.json` holds the
`scope` exported, the `authorizedScope` the identity's bounds cover, `now`, `minimumRunsPerArm` (`null`: the policy's
default) and `hasPreviousFile`, and `previousFileBom` when the file before the export starts with a UTF-8 byte order
mark (its bytes are EF BB BF, then `previous.md`'s: contract files never hold a mark). Export with an identity of `authorizedScope`'s bounds and `scope`, to the Markdown sink
on the clock `now`, writing to a file in an empty directory that first holds `previous.md`'s bytes when there is one.
Compare with `expected.json` (`outcome`, `holdoutTracked`, `exportedAt`, the `lessons` handed to the sink in order, each
`experienceId`, `revision`, `taskId`, `lessonText`, `measuredBenefit` and `exportedAt`, and `sync`, the sink's counts
or `null` when it was not called) and the file with `expected.md`, byte for byte (`expected.md` is empty when no file
was written). Each case was generated by a real .NET lessons view over the .NET in-memory store, exporting to a real
`MarkdownLessonFileSink`: the .NET half of the cross-language export, whose other halves are each port's run of the same
cases.

**lessons-html.** `page.json` is a lessons page in the lessons-view `expected.json` form (1.7), with its `scope` and a
`description`. Render it and compare with `expected.html`, byte for byte. The first case's page was listed by a real
.NET lessons view; the others are pages a view can return.

**reflection-prompt** and **reflection-output.** `input.json` is a finalize case (1.0's `finalize` form), run as one:
capture, then finalization, with the model-backed reflector built with `reflector.json`'s options (`timeoutSeconds` is
the timeout in seconds; `configureChatOptionsThrows`, when present and true, gives the reflector a
`ConfigureChatOptions` callback that throws) over a scripted chat client that answers `reply.json`: after waiting `delayMilliseconds`
(honouring cancellation) it raises (`throws`), or answers `messages`, each a `role` and its `contents` (`text`,
`reasoning`, `functionCall` with `callId` and `name`, `functionResult` with `callId` and its `text` as the result), with
the response's `modelId`. A port maps each onto its own chat client's types.

- `reflection-prompt`: the messages the client was sent (`role`, `text`), the call's options (`modelId`,
  `temperature`, `maxOutputTokens`, `toolMode`, `tools` (`null`: none), `responseFormat` with `schemaName`,
  `schemaDescription` and `schema`) and what the reflector says it showed the model.
- `reflection-output`: `expected.json` holds the `outcome` (`Validated` or `Quarantined`), `reflectionFailure` (`null`,
  or `kind`, `causeType` and `message`; `causeType` and the type in `message` are the port's own, so a port compares
  the kind, whether there is a cause, and the message with its own type in it) and `screening` (`null`, or `refusal`,
  the code, and `reason`); `expected-record.json` and `expected-event.json` are what finalization stored, in the
  finalize family's form, and must be byte-identical. These are the .NET half of the cross-language finalization: a
  .NET finalization with the model-backed reflector over a scripted answer, whose stored records a Python or Go
  finalization of the same run must equal.

**content-guard.** `cases.json` holds a corpus and what .NET's content guard answers for it (its `description` says how
to read it): for each case the run content, and for each field its folded form, the links found in it and the rule it
breaks; and the rule all the fields joined break. Run each field through the port's guard against the case's run
content and compare every value. A case marked `notRepresentableIn` holds input that language cannot hold, for the
`reason` given; that language skips it by name, and runs every other case.

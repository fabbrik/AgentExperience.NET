## What this can and cannot say

- Correctness is scored against the repository's own later history: the files the fix commit changed (at most ten), or a green re-run of the same commit (flaky). A right answer that differs from the fix actually made counts as wrong.
- Only failures whose fix was already known are handled, because a captured run lives only in memory and cannot be finalized after the process ends (story 26.2).
- Arms are assigned only on runs that had a lesson to inject, so early failures are never compared.
- One pass looks once: re-running until the verdict looks good would overstate it.
